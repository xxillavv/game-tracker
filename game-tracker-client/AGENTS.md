# Інструкції для AI-агента та контекст проєкту (Game Tracker)

## 1. Технологічний стек та інструменти
- **Фреймворк:** Next.js (App Router, версія 16.2+)
- **Мова:** TypeScript (увімкнено суворий режим / strict mode)
- **Стилізація:** Tailwind CSS
- **UI Компоненти:** Shadcn UI
- **Іконки:** Lucide React
- **Отримання даних та стан:** 
  - TanStack Query (React Query) для управління серверним станом.
  - Axios використовується *виключно* для мутацій та запитів через TanStack Query.
  - Нативний `fetch()` для стандартного отримання даних у серверних компонентах.

---

## 2. Архітектурні правила та обмеження (Constraints)
- **Серверні та клієнтські компоненти:**
  - За замовчуванням усі компоненти є серверними (Server Components - RSC).
  - Додавай `'use client'` **тільки** тоді, коли це суворо необхідно для стану (`useState`, `useEffect`), браузерних API або обробників подій (`onClick`, `onChange`).
  - Ніколи не огортай весь кореневий layout у `'use client'`. Винось клієнтський код в окремі невеликі компоненти-обгортки (наприклад, `Providers.tsx`).
- **Потік даних:**
  - Не передавай чутливу бекенд-логіку, облікові дані бази даних або секретні ключі на клієнтську сторону.
  - Явно обробляй стани завантаження та помилок через статуси TanStack Query (`isPending`, `isError` тощо).
- **Форми та інпути:**
  - Завжди скасовуй стандартну поведінку при сабміті форм (`e.preventDefault()`).
  - Кнопки всередині форм повинні чітко декларувати `type="button"`, якщо вони не призначені для сабміту форми.

---

## 3. Стиль коду та угоди
- **Назв файлів та компонентів:** 
  - Файли компонентів: PascalCase (наприклад, `GameCard.tsx`).
  - Утиліти/хелпери: camelCase.
- **TypeScript:** 
  - Завжди визначай явні інтерфейси або типи для пропсів компонентів, тіл запитів та відповідей API. Уникай використання типу `any`.
  - Завжди описуй стилі в окремому під сутність файлі, який буде розташований в папці `types` і мати назву, до прикладу `example.types.ts`.
- **Імпорти:** 
  - Використовуй абсолютні імпорти через аліас `@/` (наприклад, `@/components/...`, `@/types/...`).

---

## 4. Рекомендації для відповідей AI
- Генеруй готовий до продакшну, чистий код на TypeScript без зайвих заглушок.
- Дотримуйся межі між серверними та клієнтськими компонентами — не пропонуй робити все підряд клієнтським.
- Якщо вимога нечітка, запропонуй критерії приймання (Acceptance Criteria) перед тим, як писати великий блок коду.
